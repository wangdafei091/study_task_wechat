# 技术上下文

## 开发环境

- **开发工具**：微信开发者工具
- **开发语言**：JavaScript (ES6+)
- **布局技术**：WXML + WXSS
- **版本控制**：Git
- **运行环境**：微信小程序运行时
- **调试工具**：微信开发者工具内置调试器
- **测试框架**：Jest v29.5.0
- **包管理**：npm（支持完整的测试和开发脚本）

## 技术栈

### 核心框架
- 微信小程序原生框架（非第三方框架）
- 微信小程序组件系统
- 自定义组件机制

### 架构模式
- **领域驱动设计(DDD)**：已完全实施，架构成熟稳定
- **分层架构**：领域层、应用层、基础设施层、表现层
- **依赖注入**：通过服务管理器实现构造函数依赖注入
- **事件驱动**：基于EventBus的发布订阅模式

### 状态管理
- **服务管理器**：services/service-manager.js，提供统一的服务访问
- **事件总线**：utils/core/event-bus.js，支持优化和调试模式
- **微信小程序 globalData**：用于全局配置和状态
- **领域服务**：TaskService、StarService、RewardService、MessageService

### 存储机制
- **微信小程序本地存储 API**
  - `wx.setStorage` / `wx.setStorageSync`
  - `wx.getStorage` / `wx.getStorageSync`  
  - `wx.removeStorage` / `wx.removeStorageSync`
- **存储适配器层**：adapters/storage-adapter.js，支持缓存和命名空间
- **存储工具**：utils/storageUtils.js，提供初始化和批量操作
- **批量处理优化**：utils/batchUtils.js，广泛应用于数据操作

### 数据持久化架构
- **仓储模式**：BaseRepository及各领域仓储
- **领域模型**：Task、Star、StarGroup、Reward、Message、StarRecord
- **数据一致性**：自动检查和修复机制
- **缓存策略**：多级缓存，支持TTL和命名空间

### UI组件体系
- **小程序原生组件**：button、view、text等基础组件
- **自定义UI组件库**：
  - 进度环组件 (progressRing)
  - 任务项组件 (index-task-item)
  - 卡片容器组件 (card)
  - 任务热力图组件 (task-heatmap)
  - 即将到期任务组件 (upcomingTask)
  - 浮动菜单组件 (float-menu)
  - 星星日历组件 (star-calendar)
  - 日期选择器组件 (date-picker)

### 工具库生态
- **日志系统**：utils/logger.js，支持模块化、环境自适应、级别控制
- **日志配置**：utils/log-config.js，支持模块特定配置和动态调整
- **日志分析**：utils/log-analyzer.js，开发环境下分析console使用
- **批量处理**：utils/batchUtils.js，高性能批量数据处理
- **日期处理**：utils/dateUtils.js，全面的日期计算和格式化
- **任务工具**：utils/taskUtils.js，任务统计和分析功能
- **UI工具**：utils/uiUtils.js，界面辅助函数
- **单位换算**：utils/unit.js，屏幕适配和单位转换
- **设备信息**：utils/deviceInfo.js，环境检测和设备适配
- **格式化工具**：utils/formatUtils.js，数据格式化
- **常量定义**：utils/constants.js，系统常量和枚举

### 分包架构
- **packageChart**：数据分析和图表展示
- **packageMessage**：消息中心功能
- **packageManage**：管理功能模块
- **packageComponents**：共享组件库
- **分包服务访问**：通过app实例暴露的服务接口

### 测试框架
- **Jest v29.5.0**：单元测试和集成测试
- **测试脚本**：
  - `npm test`：运行所有测试
  - `npm run test:models`：测试领域模型
  - `npm run test:repositories`：测试仓储层
  - `npm run test:services`：测试服务层
  - `npm run test:integration`：集成测试
  - `npm run test:watch`：监听模式
  - `npm run test:coverage`：覆盖率报告

## 技术约束

### 小程序环境限制
- 单个存储项限制为1MB
- 总存储限制为10MB
- 不支持WebSockets和某些HTML5 API
- 页面栈限制为10层
- 代码包大小限制（2MB主包，8MB分包）
- 网络请求域名限制

### 性能考量
- **渲染性能**：避免频繁setData，使用批量处理
- **存储性能**：通过存储适配器和批量工具优化
- **启动性能**：优化初始化流程，延迟加载非关键服务
- **列表渲染**：大量数据使用分页或虚拟列表
- **内存管理**：及时清理过期数据和缓存

### 兼容性要求
- 支持iOS和Android微信环境
- 适配不同屏幕尺寸的设备
- 支持竖屏和横屏模式
- 考虑低端设备的性能限制
- 兼容不同版本的微信客户端

## 开发规范

### 编码规范
- 使用ES6+语法特性
- 小驼峰命名法（变量和函数）
- 大驼峰命名法（类和构造函数）
- 下划线分隔的大写字母（常量）
- 统一的缩进和格式化规则
- 详细请参见`docs/development/workflow.md`

### 架构规范
- **领域模型**：业务逻辑封装在模型内，避免贫血模型
- **仓储模式**：统一的数据访问接口，继承BaseRepository
- **服务层**：通过构造函数依赖注入，单一职责原则
- **事件机制**：使用EventBus进行组件间通信
- **详细请参见**：`.cursor/rules/architecture-rules.md`

### 组件规范
- 组件文件夹命名与组件名称一致
- 组件包含.js/.wxml/.wxss/.json四个文件
- 组件API需提供清晰的属性和事件定义
- 组件内部状态与外部传入属性分离
- 统一的UI设计规范和交互模式

### 工具函数规范
- 单一职责原则，功能明确
- 纯函数设计（无副作用）
- 模块导出一致性
- 完善的错误处理和边界检查
- 详细的JSDoc注释
- 单元测试覆盖

### 日志规范
- 使用`logger.js`统一记录日志
- 遵循日志级别定义（debug、info、warn、error）
- 包含模块名、操作描述和相关数据
- 错误日志需包含详情和上下文
- 避免过度日志和循环中频繁日志
- 支持环境自适应的日志级别
- 详细请参见`.cursorrules`中的日志规范

## 依赖管理

### 内部依赖
- **模块化加载**：通过`require`实现模块依赖
- **避免循环依赖**：明确的依赖方向和层次关系
- **服务依赖**：通过服务管理器的依赖注入
- **模块边界**：清晰的模块职责和接口定义

### 外部依赖
- **开发依赖**：Jest测试框架
- **运行时依赖**：微信小程序基础库
- **无第三方运行时依赖**：保持包体积小和安全性

### 资源依赖
- **图标和图片**：存放在`assets/icons`和`assets/images`
- **公共样式**：存放在`styles`目录，使用变量统一管理
- **动画资源**：存放在`assets/animations`目录

## 性能优化策略

### 数据处理优化
- **批量处理**：使用batchUtils避免UI阻塞
- **缓存策略**：多级缓存减少重复计算和存储访问
- **异步操作**：使用Promise和async/await避免阻塞
- **延迟加载**：非关键功能延迟初始化

### UI渲染优化
- **setData优化**：合并多个setData调用，减少渲染次数
- **数据精简**：只传输必要的数据到视图层
- **分页加载**：大型列表使用分页或虚拟列表
- **节流防抖**：频繁事件使用节流和防抖处理

### 存储优化
- **批量操作**：合并多个存储操作减少I/O
- **数据压缩**：大对象使用JSON压缩存储
- **缓存失效**：合理的缓存过期策略
- **增量更新**：只更新变化的数据部分

## 安全考量

### 数据安全
- **敏感数据加密**：用户敏感信息本地加密存储
- **日志安全**：避免在日志中记录敏感信息
- **输入验证**：所有用户输入进行验证和过滤
- **数据完整性**：关键数据使用校验和验证

### 代码安全
- **避免可预测ID**：使用时间戳和随机数生成唯一ID
- **错误处理**：避免在错误信息中泄露系统信息
- **依赖安全**：定期检查和更新依赖包
- **代码混淆**：生产环境使用代码压缩和混淆

### 运行时安全
- **数据清理**：定期清理过期和无效数据
- **内存管理**：及时释放不需要的对象和监听器
- **异常恢复**：完善的异常处理和恢复机制
- **降级策略**：关键功能失败时的降级方案
