# 领域驱动设计架构规则

## 架构分层规则

项目采用领域驱动设计架构，必须遵循以下分层规则：

```
UI/表现层 -> 应用层 -> 领域层 -> 基础设施层
```

1. **领域层**：包含所有业务逻辑和领域对象
   - `models/` 目录下定义所有领域模型
   - 所有领域对象应包含自己的业务逻辑和验证规则
   - 领域对象不应依赖外部服务或基础设施

2. **应用层**：协调领域对象之间的交互
   - `services/` 目录下定义所有应用服务
   - 服务类负责协调多个领域对象和仓储
   - 服务类不应包含业务规则，只包含流程编排

3. **基础设施层**：提供技术支持
   - `repositories/` 目录下定义所有数据访问代码
   - `adapters/` 目录下定义所有与外部系统的交互
   - `utils/` 目录下定义通用工具类

4. **UI/表现层**：用户界面处理
   - `pages/` 和 `components/` 目录下实现界面
   - UI层只应调用应用服务，不应直接操作领域对象
   - UI层负责数据展示和用户交互

## 依赖原则

1. **单向依赖**
   - 内层不能依赖外层
   - 领域层不应引用应用层和基础设施层
   - 应用层可以引用领域层，但不能引用UI层

2. **依赖注入**
   - 服务类应通过构造函数接收依赖对象
   - 允许默认实例化，但必须支持外部注入
   ```javascript
   function SomeService(options = {}) {
     this.repository = options.repository || new SomeRepository();
   }
   ```

3. **接口隔离**
   - 使用抽象接口隔离不同层之间的交互
   - 通过依赖抽象而非具体实现提高可测试性

## 领域模型规则

1. **模型完整性**
   - 领域模型必须包含所有业务属性和方法
   - 必须实现适当的验证和业务规则
   - 必须实现适当的序列化和反序列化

2. **模型命名**
   - 模型类使用大驼峰命名法，如 `Task`、`StarGroup`
   - 枚举类型使用大写下划线，如 `TASK_TYPE`
   - 模型方法使用小驼峰命名法，如 `isCompleted()`、`markAsRequired()`

3. **模型行为**
   - 领域模型应尽可能不可变
   - 状态变更应通过明确的方法进行
   - 验证逻辑应在模型内部实现

## 仓储规则

1. **命名规范**
   - 仓储类命名应以 `Repository` 结尾
   - 仓储方法应清晰描述其功能和查询条件

2. **仓储责任**
   - 仓储只负责数据存取，不实现业务逻辑
   - 仓储应提供适当的查询方法减少客户端处理
   - 仓储应处理数据存储的所有细节，客户端不需要关心实现

3. **批量处理**
   - 仓储应支持批量操作
   - 避免循环中的单条数据操作
   - 实现事务机制确保数据一致性

## 服务规则

1. **命名规范**
   - 服务类命名应以 `Service` 结尾
   - 服务方法应清晰描述业务用例

2. **服务职责**
   - 服务类协调领域对象和仓储执行业务用例
   - 服务不应包含状态，应是无状态的
   - 服务应捕获并处理异常，不应将异常传播到UI层

3. **日志记录**
   - 服务方法应记录重要操作的日志
   - 使用统一的日志工具 `logger`
   - 记录操作类型、参数和结果

## 适配器规则

1. **适配器职责**
   - 适配器封装外部系统交互
   - 适配器应提供一致的接口，隐藏实现细节
   - 适配器应处理外部系统错误并转换为内部表示

2. **缓存策略**
   - 适配器应实现适当的缓存机制
   - 提供缓存控制参数
   - 实现缓存失效机制

## 迁移规则

在从旧架构迁移到新架构的过程中，遵循以下规则：

1. **功能等价**
   - 迁移的功能必须与旧版本行为一致
   - 所有边界情况都必须考虑和测试

2. **渐进式迁移**
   - 使用服务管理器作为适配层
   - 一次只迁移一个功能模块
   - 先实现新架构，再替换旧功能

3. **兼容处理**
   - 新旧架构并行运行期间，确保数据格式兼容
   - 实现数据迁移机制
   - 服务管理器决定使用哪个实现版本

## 代码规范

1. **异步处理**
   - 统一使用 `async/await` 进行异步操作
   - 避免回调地狱和Promise链
   - 适当处理异步错误

2. **错误处理**
   - 使用 `try/catch` 捕获异常
   - 记录详细的错误信息
   - 向上层返回有意义的错误消息

3. **注释要求**
   - 所有公开方法必须有JSDoc注释
   - 复杂逻辑需要行内注释说明
   - 注释说明"为什么"而非"是什么"

## 测试规则

1. **单元测试**
   - 领域模型必须有单元测试
   - 测试应覆盖所有业务规则和边界情况
   - 使用模拟对象隔离依赖

2. **集成测试**
   - 服务层应有集成测试
   - 测试应覆盖完整的业务流程
   - 测试应验证数据一致性

## 性能规则

1. **批量处理**
   - 使用批量方法处理大量数据
   - 实现分批处理避免内存溢出
   - 使用事务确保批量操作的原子性

2. **缓存利用**
   - 合理使用多级缓存
   - 考虑数据更新频率设置缓存策略
   - 实现缓存预热和按需加载

3. **性能监控**
   - 记录重要操作的执行时间
   - 监控存储操作的性能
   - 对慢操作进行优化
