## .cursor/rules 使用指南

### 什么是 .cursor/rules

.cursor/rules 目录是 Cursor 用于存储项目规则和指南的专用目录。这些规则文件包含项目结构、开发规范、组件和工具使用说明等信息，可以帮助 Cursor 更好地理解项目并提供更准确的代码编辑和补全建议。

### 规则文件类型

规则文件分为几个主要类别：

1. **项目结构说明**：描述项目的目录结构和文件组织
2. **开发规范**：定义代码风格、命名规范和最佳实践
3. **组件使用指南**：描述自定义组件的用法和参数
4. **工具函数指南**：介绍各种工具函数的功能和使用方法
5. **数据模型说明**：定义项目中使用的数据结构和格式
6. **MemoryBank文件**：用于Cursor的上下文记忆功能

### 如何编写有效的规则文件

1. **明确主题和范围**：每个文件应该有明确的主题和内容范围
2. **使用标准Markdown格式**：遵循Markdown语法，使用适当的标题层级
3. **添加代码示例**：使用代码块提供实际示例
4. **使用链接**：添加文件链接，方便跳转到相关代码
5. **保持简洁**：内容应该简洁明了，避免不必要的重复
6. **定期更新**：随着项目发展更新规则文件

### 使用规则文件的最佳实践

1. **一致性**：保持文件命名和格式的一致性
2. **避免重复**：不同文件间避免内容重复
3. **分类组织**：按照功能或主题组织文件
4. **重点突出**：突出项目中的关键模式和规范
5. **定期审查**：定期检查和清理规则文件

### 规则文件编写示例

一个好的规则文件应该包含：

```markdown
# 组件名称

简短的描述和用途。

## 使用示例

```html
<component-name prop1="value1" prop2="value2"></component-name>
```

## 属性说明

| 属性名 | 类型 | 默认值 | 说明 |
|-------|------|-------|------|
| prop1 | String | "" | 属性1的作用 |
| prop2 | Number | 0 | 属性2的作用 |

## 事件

| 事件名 | 参数 | 说明 |
|-------|------|------|
| event1 | {value: String} | 事件1的触发条件和用途 |

## 方法

| 方法名 | 参数 | 返回值 | 说明 |
|-------|------|-------|------|
| method1 | (param: String) | Boolean | 方法1的功能描述 |
```

### 使用 MemoryBank 系统

Cursor 的 MemoryBank 系统是一种特殊的规则文件集合，用于帮助 Cursor 在会话之间保持上下文记忆。它包含以下核心文件：

1. **projectbrief.md**：项目概述和基础信息
2. **productContext.md**：产品背景和目标
3. **activeContext.md**：当前工作重点和进展
4. **systemPatterns.md**：系统架构和设计模式
5. **techContext.md**：技术框架和环境
6. **progress.md**：进度跟踪和待办事项

MemoryBank 文件应定期更新，以反映项目的最新状态和方向。建议使用"update memory bank"命令触发 Cursor 对这些文件进行全面审查。

## 文档维护建议

为确保规则文件保持最新状态，建议：

# Cursor 项目规则和最佳实践

本文档为项目开发提供指导原则和最佳实践。

## 代码结构

遵循微信小程序的标准目录结构，保持代码组织一致性：

- **pages/**: 存放页面相关文件，每个页面一个文件夹
- **components/**: 可复用组件，每个组件一个文件夹
- **utils/**: 工具函数和服务
- **assets/**: 静态资源文件
- **styles/**: 通用样式文件

## 编码规范

1. **命名约定**
   - 使用小驼峰命名法命名变量、函数和组件属性
   - 组件文件夹使用小驼峰或连字符
   - 常量使用全大写下划线分隔

2. **注释规范**
   - 组件顶部添加用途、使用方法和参数说明
   - 复杂逻辑添加行内注释
   - 函数添加注释说明功能、参数和返回值

3. **项目特定规则**
   - 所有关键操作添加日志，使用logger.js提供的统一接口 `logger.log(module, message, data)`
   - 任务状态变更必须通过 `taskManager` 进行
   - 存储操作优先使用 `storageUtils` 工具函数
   - 批量处理操作使用 `batchUtils` 工具函数
   - 通用UI操作使用 `uiUtils` 工具函数
   - 常量定义使用 `constants.js` 统一管理

## 组件开发规范

1. **组件结构**
   - 为组件创建独立文件夹，包含 js、wxml、wxss 和 json 文件
   - 组件属性使用 properties 定义，并提供默认值
   - 组件事件使用 this.triggerEvent() 触发

2. **组件通信**
   - 使用属性传递数据给子组件
   - 使用事件从子组件向父组件传递信息
   - 复杂状态共享使用全局事件总线

3. **UI规范**
   - 按钮高度统一为90rpx
   - 输入框高度统一为90rpx
   - 卡片内边距统一为30rpx
   - 表单项垂直间距为24rpx
   - 相关元素组间距为12rpx
   - 所有组件适配不同屏幕尺寸和横竖屏模式

## 核心业务规则

1. **任务管理**
   - 任务状态：0(未完成)、1(已完成)、'canceled'(已取消)、'overdue'(已逾期)
   - 任务数据操作统一通过 taskManager 进行
   - 重复任务编辑需提供单次/系列选择
   - 任务永久删除前需确认
   - 必做任务处理优先级高于普通任务

2. **积分机制**
   - 积分有效期使用自然周期计算（自然周/月/季度/半年/年）
   - 积分有效期类型统一使用 `pointsExpiry` 字段，有效值包括：'permanent', 'week', 'month', '3months', '6months', '12months'
   - 积分有效期显示文本应使用 `Constants.POINTS_EXPIRY.TEXT` 映射获取
   - 所有显示积分有效期的组件必须将 `Constants` 对象加入组件 data
   - 已完成任务显示确切到期时间，未完成任务显示"完成后保留xx"
   - 特殊情况处理：周日完成的week任务、月末完成的month任务等，显示"当天24点失效"
   - 确保正确处理闰年、跨年等边缘情况

3. **消息通知**
   - 消息创建统一通过 messageManager 处理
   - 消息类型：任务、系统、奖励
   - 消息最多保留100条，超出自动清理

## 性能优化准则

1. **渲染优化**
   - 避免不必要的setData操作
   - 合并setData调用
   - 使用 wx:if 控制复杂组件渲染

2. **数据处理**
   - 大量数据操作在JS线程进行，避免阻塞渲染
   - 批量任务处理使用batchUtils，提供进度显示
   - 列表渲染使用虚拟列表优化

3. **资源使用**
   - 图片资源使用适当尺寸和格式
   - 延迟加载非关键资源
   - 使用统一存储工具storageUtils缓存常用数据

## 错误处理和日志

1. **错误处理**
   - 网络请求添加超时和错误处理
   - 页面跳转包含参数验证
   - 数据操作包含兜底策略

2. **日志规范**
   - 使用logger.js记录日志，统一格式：`logger.log(module, message, data)`
   - 错误日志记录完整上下文
   - 性能关键点记录时间戳
   - 使用不同级别的日志：
     - log(普通): 一般性操作记录
     - info(流程节点): 重要流程开始/结束
     - debug(调试): 详细信息，仅开发阶段使用
     - warn(警告): 可能会导致问题但不影响正常运行
     - error(错误): 严重错误或异常情况
   - 对象日志使用精简版，仅记录关键字段
   - 批量处理操作记录当前进度
   - 异步操作在开始和结束添加日志

## 特定问题解决方案

1. **适配问题**
   - 使用 rpx 单位实现响应式布局
   - 使用 unit.js 工具处理特殊设备
   - 针对横屏模式提供专用布局处理
   - 确保不同设备上UI元素高度和间距一致
