# 文档管理规则

## 文档位置

所有项目文档必须统一存放在项目根目录的 `docs/` 文件夹下，按照以下分类组织：

```
docs/
├── architecture/       # 架构文档
│   ├── project_structure.md    # 项目结构
│   ├── data_models.md          # 数据模型
│   ├── system_architecture.md  # 系统架构
│   ├── domain-model-architecture.md # 领域模型架构
│   ├── star_points_system.md   # 星星有效期与消费机制
│   └── optimization_summary.md # 优化总结
├── development/       # 开发指南
│   ├── workflow.md             # 开发工作流程
│   ├── coding_standards.md     # 编码规范
│   ├── troubleshooting.md      # 常见问题解决
│   └── CHANGELOG.md            # 更新日志
├── api/               # API文档
│   └── utils_guide.md          # 工具函数指南
├── user/              # 用户手册
│   ├── guide.md                # 用户指南
│   └── faq.md                  # 常见问题解答
└── README.md          # 项目总览
```

## 命名规则

- 文档文件使用小写字母和连字符命名，如 `project-structure.md`
- 每个文档应有明确的标题和简要描述
- 文档内部使用Markdown格式，保持格式一致性

## 文档更新流程

**重要事项**：代码修改不会自动更新文档，需要开发者手动维护。

在以下情况下，必须更新相关文档：

1. **修改领域模型时**：
   - 更新 `docs/architecture/domain-model-architecture.md` 文档
   - 更新 `docs/architecture/data_models.md` 中对应的数据模型
   - 如果修改了领域规则，确保更新对应的业务规则描述

2. **修改仓储实现时**：
   - 更新 `docs/architecture/domain-model-architecture.md` 中的仓储层描述
   - 确保数据持久化机制的描述与实际实现一致

3. **修改服务层时**：
   - 更新 `docs/architecture/domain-model-architecture.md` 中的服务层描述
   - 确保服务职责、接口和实现的描述保持同步

4. **修改适配器时**：
   - 更新适配器相关文档，确保与实际实现一致
   - 记录任何底层存储或API变更

5. **添加新组件或工具函数时**：
   - 在对应指南中添加新组件或函数的说明
   - 包含使用示例和参数说明

6. **修复问题时**：
   - 如果问题与文档描述不符，更新文档
   - 考虑在故障排除指南中添加相关问题的解决方案

## 领域驱动设计文档要求

对于领域驱动设计架构，文档必须清晰描述：

1. **领域模型**
   - 实体的属性、方法和业务规则
   - 值对象的定义和不变性
   - 实体之间的关系和约束
   - 领域事件的定义和处理

2. **仓储层**
   - 仓储接口和实现
   - 查询方法和条件
   - 批量操作和事务处理
   - 缓存策略和失效机制

3. **服务层**
   - 服务职责和边界
   - 服务之间的协作和依赖
   - 业务流程和状态转换
   - 事件处理和响应

4. **适配器层**
   - 存储适配器的实现和接口
   - 与外部系统的集成点
   - 技术选型和约束

## 日志规范

使用 `logger` 工具统一格式，遵循以下格式：

```javascript
const logger = require('../../utils/logger');

// 记录普通信息
logger.log('componentName', '操作描述', 变量);

// 记录流程节点信息
logger.info('componentName', '重要流程点', 变量);

// 记录警告信息
logger.warn('componentName', '警告描述', 变量);

// 记录错误信息 
logger.error('componentName', '错误描述', 错误对象);
```

### 日志记录要点

1. **关键点必须添加日志**：
   - 领域实体的状态变更
   - 重要业务规则的应用
   - 数据持久化操作
   - 异步操作的开始和结束
   - 服务层的事务处理

2. **日志内容要求**：
   - 保持简洁明了，包含必要信息
   - 对象日志使用精简版，仅记录关键字段
   - 记录操作类型、对象ID和关键参数
   - 错误日志需包含错误详情和上下文

3. **避免过度日志**：
   - 不记录频繁重复的常规操作
   - 不记录大量无关紧要的信息
   - 循环中谨慎使用日志
   - 过大对象使用精简版记录关键属性

## 文档审核与清理

- 每当领域模型发生变化时，立即审核并更新相关文档
- 移除过时的文档内容，确保文档的准确性
- 保持文档简洁，避免冗余和重复描述
