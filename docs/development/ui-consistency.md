# UI一致性指南

## 概述
本文档记录项目中UI组件的一致性规范和改动历史，确保整个应用的视觉体验统一。

## 组件样式规范

### 日历组件样式统一（2024年更新）

#### 背景
- 任务编辑页面（task-heatmap组件）和分析页面（star-calendar组件）的日历样式存在差异
- 为提升用户体验，统一两个日历的基础视觉样式

#### 统一的样式规范

1. **日历格子基础样式**
   - 尺寸：`width: 14.28%`, `aspect-ratio: 1`（正方形比例）
   - 内边距：`padding: 10rpx 0`
   - 圆角：`border-radius: 8rpx`
   - 过渡效果：`transition: background-color 0.2s`

2. **日期数字样式**
   - 字体大小：`32rpx`
   - 字体粗细：`font-weight: 600`
   - 行高：`line-height: 1.2`
   - 顶部间距：`margin-top: 6rpx`

3. **星期标题样式**
   - 字体大小：`26rpx`
   - 颜色：`#555`
   - 内边距：`padding: 8rpx 0`
   - 底部边框：`border-bottom: 1rpx solid #f0f0f0`

4. **"今天"标识样式**
   - 背景色：`rgba(66, 133, 244, 0.15)`
   - 边框：`1rpx solid rgba(66, 133, 244, 0.3)`
   - 圆角：`8rpx`
   - 日期数字：`color: #4285F4`, `font-weight: 700`

#### 信息层级优化（2024年12月更新）

**问题背景**：日期数字与任务统计信息的视觉权重相等，造成视觉混乱

**优化方案**：
1. **保持日期数字不变**：`32rpx`（主要信息）
2. **缩小任务信息**：从 `20rpx` 减小到 `14rpx`（次要信息）
3. **降低视觉权重**：
   - 透明度从 `0.9` 降至 `0.7`
   - 字体粗细从 `600` 降至 `500`
   - 分隔符从 `16rpx` 减小到 `12rpx`
4. **视觉层级比例**：从 1.6:1 提升到 2.3:1

**设计原理**：
- 遵循"主次分明"的界面设计原则
- 通过字体大小、透明度和字重建立清晰的信息层级
- 减少视觉噪音，提升信息识别效率

#### 保持差异的功能性内容

1. **任务编辑页面（task-heatmap）**
   - 显示内容：任务数量（`{count}T`）和星星总数（`{starsTotal}⭐`）
   - 特色功能：热力图背景色（4个压力等级）
   - 字体大小：`14rpx`（优化后）

2. **分析页面（star-calendar）**
   - 显示内容：获得星星（`+{earned}`）和扣除星星（`-{deducted}`）
   - 特色功能：星星动画效果
   - 字体大小：`20rpx`

#### 改动记录

**2024年日历样式统一**
- 文件：`components/task-heatmap/task-heatmap.wxss`
- 改动内容：
  1. 日期格子从固定高度`48rpx`改为正方形比例`aspect-ratio: 1`
  2. 日期数字字体从`20rpx`改为`32rpx`，字重从`500`改为`600`
  3. 星期标题字体从`22rpx`改为`26rpx`，颜色从`#999`改为`#555`
  4. "今天"标识从底部小圆点改为背景高亮样式
  5. 清理冗余CSS代码（移除不再使用的`.star-risk`和`.task-required-tag`类）

**2024年12月信息层级优化**
- 文件：`components/task-heatmap/task-heatmap.wxss`
- 改动内容：
  1. 任务信息字体从`20rpx`减小到`14rpx`
  2. 透明度从`0.9`降至`0.7`
  3. 字重从`600`降至`500`
  4. 分隔符从`16rpx`减小到`12rpx`
  5. 建立2.3:1的主次信息视觉比例

## 颜色系统

## 维护指南

1. **修改UI样式前**
   - 检查是否有其他组件使用相同的样式
   - 评估改动对用户体验的影响

2. **修改后**
   - 更新本文档记录改动
   - 在相关组件中添加日志记录
   - 测试在不同设备上的显示效果

3. **审查要点**
   - 保持视觉一致性
   - 确保功能性差异得到保留
   - 避免过度设计
