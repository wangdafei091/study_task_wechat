   - 验收：日期格式化统一使用 dateUtils

2. **在 BaseRepository 添加用户过滤器**
   - 重复位置：所有仓储文件（task-repository、star-repository 等）
   - 实施方案：
     - 添加 `withUserFilter()` 方法自动处理用户过滤
     - 添加 `queryByUser()` 方法简化用户查询
     - 更新现有仓储使用新方法
   - 验收：用户过滤逻辑统一到 BaseRepository

3. **创建错误处理装饰器**
   - 重复位置：多个服务文件（user-service、reward-service 等）
   - 实施方案：
     - 创建 `utils/errorHandler.js` 统一错误处理
     - 提供装饰器模式自动包装方法
     - 标准化错误日志格式和返回值
   - 验收：错误处理模式统一

4. **统一常量定义**
   - 重复位置：多个模型文件（状态常量、颜色值等）
   - 实施方案：
     - 统一到 `utils/constants.js`
     - 使用枚举类型替代字符串常量

**验收标准**：

## 附录：文档使用规范

### 里程碑创建流程

1. **讨论确认**：在"待讨论"区域提出，与用户讨论确认
2. **创建里程碑**：确认后，在"里程碑规划"区域创建
3. **拆解任务**：将里程碑拆解为多个独立价值的任务
4. **标记状态**：初始状态为"待启动"

### 状态说明

| 状态 | 说明 | 示例 |
|------|------|------|
| **待讨论** | 未确认的想法或方向 | 是否需要提升测试覆盖率？ |
| **待启动** | 已规划，未开始执行 | 提升StarService测试覆盖率 |
| **进行中** | 已启动，正在执行 | 提升StarService测试覆盖率 |
| **已完成** | 已完成，待归档 | 提升StarService测试覆盖率 |

### 归档流程

1. 里程碑下的所有任务完成
2. 在 ROADMAP.md 标记为"已完成"
3. 整理到 CHANGELOG.md
4. 从 ROADMAP.md 移除
