## 领域驱动设计架构

项目现已完整采用领域驱动设计（DDD）架构，核心模块包括：

### 领域层
- **领域模型**：实现了任务(Task)、星星(Star)、星星分组(StarGroup)、奖励(Reward)、星星记录(StarRecord)等核心模型
- **业务规则**：将业务规则封装在领域模型内，确保业务一致性
- **领域事件**：实现状态变更通知机制，保持模块间松耦合

### 应用层
- **服务类**：提供StarService、RewardService等服务，协调领域对象间交互
- **用例实现**：通过服务类实现完整的业务流程

### 基础设施层
- **仓储实现**：提供领域对象的持久化功能
- **适配器**：封装底层存储、API调用等细节

### 界面层
- **页面**：处理用户交互，通过服务类调用领域功能
- **组件**：使用统一的UI风格和交互模式

详细架构设计请参考[领域模型架构](architecture/domain-model-architecture.md)文档。领域模型和数据模型详情请查看[数据模型](architecture/data_models.md)文档。

## 文档管理规则

所有文档遵循以下规则：

1. 文档统一存放在 `docs/` 目录下，按类别组织
2. 使用 Markdown 格式编写，保持格式一致性
3. 使用小写字母和连字符命名文档文件，如 `project-structure.md`
4. 每个文档应有明确的标题和简要描述
5. 修改代码时，同步更新相关文档
6. 定期清理过时文档内容

## 文档格式规范

为确保文档的一致性和可读性，所有项目文档应遵循以下格式规范：

### 标题层级使用规范

1. **文档标题**：使用一级标题 `# 标题`，每个文档只能有一个一级标题
2. **主要部分**：使用二级标题 `## 主要部分`
3. **子部分**：使用三级标题 `### 子部分`
4. **小节**：使用四级标题 `#### 小节` 
5. **避免使用**：五级或更深层级的标题，保持文档结构清晰

### 代码块格式

1. **代码块**：使用三个反引号包裹，并标明语言类型
   ```javascript
   // 正确示例
   ```javascript
   function example() {
     return true;
   }
   ```
   ```

2. **行内代码**：使用单个反引号包裹，如 `function`、`class` 等

### 列表格式

1. **有序列表**：使用数字加点，如 `1. 第一项`
2. **无序列表**：使用连字符，如 `- 列表项`
3. **嵌套列表**：子项缩进两个空格

### 表格格式

使用标准Markdown表格语法，并保持列对齐：

```
| 列1 | 列2 | 列3 |
| --- | --- | --- |
| 内容 | 内容 | 内容 |
```

### 其他格式要求

1. **强调**：使用双星号加粗重要内容，如 `**重要内容**`
2. **链接**：使用方括号加圆括号，如 `[链接文字](链接地址)`
3. **图片**：使用感叹号加方括号和圆括号，如 `![图片描述](图片地址)`
4. **引用**：使用大于号，如 `> 引用内容`
5. **分隔线**：使用三个连字符，如 `---`

## 最新功能：星星有效期和消费机制

### 星星分组管理
- 按过期时间将星星分组存储
- 实现"先过期先使用"的消费策略
- 自动清理过期星星
- 数据一致性检查机制

### 实现原理
1. 每次任务完成时，根据设置的有效期类型计算星星过期时间
2. 将获得的星星添加到对应过期时间的星星分组中
3. 消费星星时，优先使用即将过期的星星
4. 定期清理已过期的星星，确保数据一致性

### 过期预测功能
- 基于星星分组数据计算未来星星过期趋势
- 提供可视化图表展示过期预测
- 帮助用户合理规划星星使用

## 日志规范
为便于追踪和调试，在关键位置添加日志。使用 `logger` 工具统一格式，例如：

```javascript
const logger = require('../../utils/logger');

// 记录普通信息
logger.log('componentName', '操作描述', 变量);

// 记录流程节点信息
logger.info('componentName', '重要流程点', 变量);

// 记录警告信息
logger.warn('componentName', '警告描述', 变量);

// 记录错误信息 
logger.error('componentName', '错误描述', 错误对象);
```

### 日志记录要点
1. **关键点必须添加日志**：
   - 任务创建、编辑、删除和状态变更
   - 重要数据的读取和存储操作
   - 页面重要生命周期事件
   - 用户关键操作
   - 异步操作的开始和结束
   - 所有积分计算和有效期处理过程

2. **日志内容要求**：
   - 保持简洁明了，包含必要信息
   - 对象日志使用精简版，仅记录关键字段
   - 记录操作类型、对象ID和关键参数
   - 错误日志需包含错误详情和上下文
   - 批量处理操作记录当前进度

3. **避免过度日志**：
   - 不记录频繁重复的常规操作
   - 不记录大量无关紧要的信息
   - 循环中谨慎使用日志
   - 过大对象使用精简版记录关键属性
