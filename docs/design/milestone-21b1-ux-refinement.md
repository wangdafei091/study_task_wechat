## 需求分析

### 背景

`M21B1` 已经完成“任务模板基础闭环”，能力上已经具备：

- 家长管理模板
- 新建任务时选择模板并填充表单
- 模板跨设备同步

但基于模拟器实操反馈，当前交互仍有明显体验问题：模板作为“辅助工具”在任务创建页中过于抢眼，容易让用户误以为“必须先有模板才能继续添加任务”；模板标签信息层级偏重、信息重复；模板管理页按钮布局不协调；模板编辑页和任务编辑页的心智不一致，尤其“日期策略”概念过于技术化，给用户造成理解负担。

在这轮实操中又暴露出一个更底层的问题：当前模板编辑页仍要求用户维护“日期范围”，而模板的真实用途是帮助用户保存高频任务的默认规则。对用户来说，模板更像“任务默认规则集合”，而不是“某一次任务实例的完整快照”。继续让用户输入绝对日期，会持续制造“这个日期到底该怎么填”的困惑。

因此，需要在不改变 `M21B1` 基础闭环目标的前提下，新增一个短周期的体验优化阶段，把模板入口、模板展示、模板编辑页和模板管理页的交互压顺，并同步修正模板日期语义，再进入 `M21B2`。

### 功能定位

`M21B1-UX` 的目标不是新增新的业务入口，而是修正现有模板能力的视觉层级、交互路径和用户心智：

- 让“直接添加任务”继续保持主流程地位
- 让“模板”明确呈现为加速器，而不是前置步骤
- 降低模板标签和模板卡片的信息密度
- 让模板编辑页尽量复用任务编辑页的结构和语言
- 让模板回到“保存默认规则”的语义，而不是保存绝对日期实例
- 让模板编辑页中的“当前预览 / 重复提示”直接描述用户结果，而不是暴露内部规则推导过程

### 体验问题归纳

1. `task-edit` 页模板区当前存在“宣宾夺主”的问题
2. “查看全部”放在“添加任务”卡片标题动作区，视觉层次过重
3. 模板标签当前高度偏大，且同时显示模板名与任务名，信息重复
4. 模板管理页卡片底部 4 个按钮同权排布，不协调
5. “模板名称”和“任务名称”同时强暴露，概念负担偏高
6. 模板管理页空态同时出现头部 `新建模板` 和主体 `创建第一个模板`，语义重复，页面显得啰嗦
7. 模板管理页外层边距、卡片留白和筛选区视觉语言与现有任务管理页不一致，像独立后台页
8. 模板编辑页“日期策略”和“日期范围”一起暴露，用户难以理解模板该如何填写
9. 模板编辑页与任务编辑页布局差异较大，学习成本偏高
10. 当前模板页把“选择模板”和“管理模板”混在同一页面模式里，导致高频的“选模板”不够突出，低频的“新建/编辑模板”反而抢占首屏焦点
11. 模板编辑页“当前预览”卡片只显示纯值胶囊，例如只显示 `无`、`永久`，用户无法快速判断该值对应的是提醒、重复还是有效期
12. 模板编辑页重复提示文案仍在描述“系统内部调整过程”，没有直接告诉用户“最终会从哪一天开始生效、持续如何计算”，普通用户较难理解
13. 模板编辑页“当前预览”第一行胶囊虽已具备正确语义，但当前视觉更接近筛选标签，和页面主表单的风格仍有轻微割裂，不够像轻量摘要信息
14. “默认持续天数”当前采用标题一行、输入框一行的双行布局，破坏了“时间与重复”分组里大多数设置项的单行节奏
15. 模板页导航标题、卡片标题和模式文案同时出现“选择模板 / 管理模板 / 模板管理”，命名不一致且语义重复
16. 选择模板页首屏的搜索、状态、排序、分类筛选同时出现，视觉上比模板列表更抢眼，造成“头重脚轻”
17. 选择模板页没有清晰告诉用户“下面的卡片可直接点击回填”，搜索筛选器反而先吸走注意力
18. 管理模板页沿用了和选择页几乎相同的搜索筛选结构，但管理场景并不需要这么重的首屏筛选复杂度
19. 管理模板页里“新建模板”和每张卡片上的“编辑”同时高亮，用户容易分不清页面主动作和卡片主动作
20. 重复模板当前只有“长期有效 / 默认持续天数”两种结束语义，用户如果在周中创建任务，希望自动填充到“本周结束”或“本月结束”，当前并不支持

### 范围

**包含**：

- 调整 `task-edit` 页模板入口的视觉层级与文案
- 重做任务页模板标签样式和信息展示策略
- 调整模板管理页的主要入口和卡片动作分层
- 简化模板编辑页字段暴露，移除“日期策略”的显式用户输入
- 调整模板日期字段语义：不再要求用户维护绝对日期范围
- 让模板编辑页整体布局尽量向任务编辑页靠拢

**不包含**：

- 不改变模板同步语义
- 不改变模板使用、创建、启停、删除等业务能力
- 不引入 `M21B2` 的推荐模板、相似任务聚类、从历史任务保存模板
- 不重新设计孩子端权限模型
- 不考虑旧数据兼容和迁移；模板功能尚未正式上线，本期直接收敛为最终语义

### 成功标准

- 用户进入 `task-edit` 页时，不再感觉“必须先创建模板”
- 模板区视觉上从“主功能模块”降为“快捷填充辅助条”
- 模板标签单层展示，阅读成本明显下降
- 模板相关页面的主次任务清晰：从任务页进入时先服务“选择模板”，管理能力降为次级入口
- 模板管理页空态不再出现重复创建入口，整体视觉节奏与任务管理页一致
- 模板页标题、页内分区标题和入口文案统一，不再出现“选择模板 / 管理模板 / 模板管理”混用
- 模板页首屏视觉焦点回到模板列表，而不是搜索筛选器
- 选择模板场景下，用户能一眼理解“点击卡片即可回填”
- 管理模板场景下，“新建模板”是页面动作，“编辑模板”是卡片动作，层级清晰
- 模板编辑页不再出现让普通用户困惑的“日期策略 / 绝对日期范围”输入
- 模板编辑页与任务编辑页的布局相似度明显提高
- 用户能够自然理解：模板保存的是默认规则，任务日期在创建时再落定
- 用户在“当前预览”卡片中看到的每个胶囊都能一眼判断语义归属
- 自定义重复与不同结束方式组合场景下，用户能够读懂“将从哪一天开始”和“结束日期如何计算”
- “当前预览”胶囊视觉上更像摘要信息，不会比主表单更抢眼
- `结束方式 / 持续天数` 与同组设置项保持一致的一行式布局，整体节奏更整齐
- 用户在周中使用重复模板时，可以直接得到“到本周结束”或“到本月结束”的时间范围，而不必手工再改结束日期

## 技术方案

### 方案概述

`M21B1-UX` 采用“入口降权 + 信息架构收敛 + 展示减负 + 语义校正 + 编辑同构”的方案。

前端上不新增页面，也不新增后端 REST 路径，但会对模板字段语义和前后端模板服务的持久化契约做一次收敛调整。工作重点落在现有 3 个页面、前端模板服务与后端模板服务：

- [task-edit.wxml](/Users/wangdafei/code/study_task_wechat/pages/task-edit/task-edit.wxml)
- [task-template-manage.wxml](/Users/wangdafei/code/study_task_wechat/packageManage/pages/task-template-manage/task-template-manage.wxml)
- [task-template-edit.wxml](/Users/wangdafei/code/study_task_wechat/packageManage/pages/task-template-edit/task-template-edit.wxml)
- [task-template-service.js](/Users/wangdafei/code/study_task_wechat/services/task-template-service.js)
- [backend/services/taskTemplateService.js](/Users/wangdafei/code/study_task_wechat/backend/services/taskTemplateService.js)

### 关键策略

#### 1. 任务页模板入口降权

模板区从“卡片内独立模块”调整为“快捷填充辅助条”：

- 标题文案改为 `快捷填充`
- 有模板时，右侧操作文案改为 `更多模板 >`
- 无模板时，不显示右侧独立入口
- 不再使用强提示式 `创建第一个模板` 按钮
- 无模板时只显示一行弱提示：`还没有模板，去创建 >`

这样可以明确：主流程仍然是直接填写任务表单，模板只是帮助用户减少录入成本的快捷工具。

#### 2. 任务页模板标签减负

模板标签改为更紧凑的单层胶囊：

- 降低高度和内边距
- 默认只显示一个名称
- 当 `name` 非空且与 `taskPayload.title` 不同时，显示 `name`
- 当 `name` 为空，或与 `taskPayload.title` 相同时，显示 `taskPayload.title`
- 标签中不再重复展示第二行任务名称

类型色可保留，但应降低饱和度，避免抢过任务表单主视觉。

#### 3. 模板页信息架构收敛

模板页继续保留同一物理页面与路由，但不再通过页面标题和卡片标题反复强调“选择模板 / 管理模板”。

统一原则：

- 小程序导航栏标题固定为 `任务模板`
- 页面内容区不再重复出现同名大标题卡片
- 页面主体采用页内双 tab：
  - `选择模板`
  - `管理模板`
- 从 `task-edit` 进入时默认激活 `选择模板`
- 从明确的管理入口进入时默认激活 `管理模板`

这样可以把“功能域”与“当前子任务”分开表达：

- `任务模板` 是功能域
- `选择模板 / 管理模板` 是页内子任务

用户不会再被“页面标题叫选择模板、卡片标题又叫选择模板、入口又叫管理模板”的重复命名打断理解。

#### 3.1 选择模板与管理模板的职责拆分

页内双 tab 的职责固定为：

- `选择模板`
  - 服务高频“选一个模板快速回填”
  - 模板卡片整体可点击
  - 卡片不出现 `编辑` 主按钮
  - 页面要显式提供一行轻提示：`点击模板即可回填到任务表单`
- `管理模板`
  - 服务低频“新建、编辑、启停、删除模板”
  - 页面级主动作是 `新建模板`
  - 卡片级主动作是“进入编辑”
  - `启用/停用` 与 `删除` 统一收纳到 `更多`

这样可以把高频“选模板”和低频“管模板”彻底拆开，避免低频维护动作继续压过主线任务。

#### 3.2 搜索筛选区降权与简化

模板页仍保留搜索与分类查找能力，但首屏不再堆叠多组筛选器。

`选择模板` tab：

- 保留一个轻量搜索框
- 搜索范围明确为：模板别名、任务名称、模板说明
- 默认只展示“已启用模板”
- 停用模板不进入 `选择模板` tab 列表，避免把不可用项混入高频选择场景
- 只保留 `习惯 / 学习 / 兴趣` 三个分类筛选
- 分类筛选采用“单选可取消”规则：
  - 点击某个分类后，仅显示该分类模板
  - 再次点击当前已选分类，即取消筛选并回到全量列表
- 不再显式展示：
  - `全部`
  - `全部状态 / 仅启用 / 仅停用`
  - `最近使用 / 使用次数`
- 列表排序固定为：
  - 最近使用优先
  - 使用次数作为次级排序
  - 最近创建/最近编辑时间作为第三排序键，保证刚创建的模板不会因“尚未使用”而沉底

`管理模板` tab：

- 首屏保留轻量搜索框和分类筛选
- 不再把状态筛选、排序切换作为常驻首屏控件
- 列表默认按以下固定顺序排序：
  - 最近编辑时间优先
  - 最近使用时间次级排序
  - 创建时间第三排序
- 停用状态通过卡片状态标签识别
- 如后续确有必要，再在 `更多筛选` 中补充状态过滤，但不作为本期首屏默认结构

视觉约束：

- 搜索与筛选区整体应弱于模板列表
- 搜索框高度、边距、背景强度与 `task-edit` 页保持同体系，不营造“后台筛选面板”感
- 分类筛选应表现为轻量辅助，不得比模板卡片标题和主动作更抢眼

这样可以解决当前“筛选器比模板更像主角”的问题，也减少用户为了完成一次简单模板选择而理解过多控制项。

#### 4. 模板名称与任务名称的语义收敛

数据模型层面继续保留两个字段，但交互上弱化“双名称”概念：

- 保留 `taskPayload.title` 作为真实任务名称
- `name` 仅作为“模板别名（可选）”
- 编辑页允许用户不主动填写别名
- 保存时统一执行回填规则：`name = alias.trim() || taskPayload.title.trim()`
- 展示时统一执行回退规则：
  - 若 `name` 为空，显示 `taskPayload.title`
  - 若 `name === taskPayload.title`，只显示一份名称
  - 若两者不同，仅显示 `name` 作为主名称，任务名称不在标签中重复展示

第一版不强制改数据库结构，先通过文案和展示策略收敛用户认知。

#### 5. 模板日期语义校正

模板编辑页不再让用户维护绝对 `日期范围`，也不再向用户暴露 `dateStrategy.mode`。

补充约束：

- `星星有效期` 的正式语义以 [milestone-21b1-task-template-foundation.md](/Users/wangdafei/code/study_task_wechat/docs/design/milestone-21b1-task-template-foundation.md) 中的 canonical contract 为准。
- 本轮页面文案统一使用：
  - `永久`
  - `本周结束`
  - `本月结束`
  - `本季度结束`
- 本轮不在页面中引入“到账后7天”这类滚动过期选项。

模板应保存的是“任务默认规则”，而不是“某次任务实例快照”。因此字段分层调整为：

**模板主字段**：

- `任务名称`
- `类型`
- `星星`
- `星星有效期`
- `必做任务`
- `任务描述`
- `是否全天`
- `时间范围`
- `重复方式`
- `提醒`
- `结束方式`
- `持续天数（仅结束方式 = 持续天数时显示）`

**创建任务时自动决定的字段**：

- `开始日期`
- `结束日期`

具体规则固定为：

- 非重复模板：
  - 编辑页不展示日期输入
  - 使用模板时统一填充为 `今天 -> 今天`
  - 不展示 `结束方式`
  - 内部固定 `endMode = 'same-day'`
  - `durationDays = 1`
- 重复模板：
  - 不展示绝对开始日期输入
  - 不再暴露 `长期有效` 独立开关
  - 改为统一维护 `结束方式`
  - `结束方式` 固定提供四个选项：
    - `本周结束`
    - `本月结束`
    - `持续天数`
    - `长期有效`
  - 本期不提供 `本季度结束`，避免把任务时间范围配置做得比当前用户心智更重
  - 仅当 `结束方式 = 持续天数` 时，展示 `持续天数`
  - 使用模板时以“今天”为参考日，寻找首个符合重复规则的生效日
  - 若 `结束方式 = 长期有效`，则结束日期为空
  - 若 `结束方式 = 持续天数`，则结束日期 = `首个匹配生效日 + durationDays - 1`
  - 若 `结束方式 = 本周结束`，则结束日期 = `首个匹配生效日所在自然周的周日`
  - 若 `结束方式 = 本月结束`，则结束日期 = `首个匹配生效日所在自然月的月末`

持久化规则调整为：

- `taskPayload.startDate/endDate/repeat.startDate/repeat.endDate` 不再代表用户手工维护的模板源字段
- 页面保存时仍可生成规范化的日期占位值，以保持与现有任务表单结构对齐
- `dateStrategy` 新增：
  - `endMode`
  - `durationDays`
- `dateStrategy.mode` 继续自动推导：
  - 重复类型为 `none` 时：`today`
  - 重复类型不为 `none` 时：`inherit-repeat-rule`

`autoShiftExpiredEndDate` 在本期也不再暴露为显式开关，内部固定为 `true`。由于模板功能尚未正式上线，本期不额外设计旧数据兼容策略。

执行边界补充：

- 本轮不做旧模板数据兼容。
- 若开发/测试环境中已存在按旧语义写入的模板数据，可直接清空 `task_templates` 表数据后再验证，不要求保留旧数据。
- 本轮不涉及 `task_templates` 表结构变更；`durationDays` 进入 `date_strategy` JSON，不新增数据库 migration，也不需要删表重建。
- 本轮同步移除仅服务旧 `长期有效` 开关和旧 `默认持续天数` 单一语义的页面状态、事件、样式、预览文案与测试夹具，不保留双语义并存的过渡代码。

**UI 字段到持久化字段映射**：

| UI 语义 | `taskPayload` | `dateStrategy` | 说明 |
|------|------|------|------|
| 非重复模板 | `startDate=todayPlaceholder` `endDate=todayPlaceholder` `hasNoEndDate=false` `repeat.startDate=todayPlaceholder` `repeat.endDate=todayPlaceholder` | `mode='today'` `endMode='same-day'` `durationDays=1` | 占位日期仅用于通过既有规范化与校验，不再代表模板真实业务语义 |
| 重复模板 + 长期有效 | `startDate=todayPlaceholder` `endDate=''` `hasNoEndDate=true` `repeat.startDate=todayPlaceholder` `repeat.endDate=''` | `mode='inherit-repeat-rule'` `endMode='no-end'` `durationDays=null` | 创建任务时以“今天”为参考日寻找首个匹配生效日，无结束日期 |
| 重复模板 + 持续 N 天 | `startDate=todayPlaceholder` `endDate=todayPlaceholder+N-1` `hasNoEndDate=false` `repeat.startDate=todayPlaceholder` `repeat.endDate=todayPlaceholder+N-1` | `mode='inherit-repeat-rule'` `endMode='duration'` `durationDays=N` | 占位日期用于和现有模型结构对齐；真实结束日期在应用模板时按“首个匹配生效日”重新计算 |
| 重复模板 + 本周结束 | `startDate=todayPlaceholder` `endDate=endOfWeek(todayPlaceholder)` `hasNoEndDate=false` `repeat.startDate=todayPlaceholder` `repeat.endDate=endOfWeek(todayPlaceholder)` | `mode='inherit-repeat-rule'` `endMode='week-end'` `durationDays=null` | 占位结束日期仅用于结构对齐；真实结束日期在应用模板时按“首个匹配生效日所在自然周”重新计算 |
| 重复模板 + 本月结束 | `startDate=todayPlaceholder` `endDate=endOfMonth(todayPlaceholder)` `hasNoEndDate=false` `repeat.startDate=todayPlaceholder` `repeat.endDate=endOfMonth(todayPlaceholder)` | `mode='inherit-repeat-rule'` `endMode='month-end'` `durationDays=null` | 占位结束日期仅用于结构对齐；真实结束日期在应用模板时按“首个匹配生效日所在自然月”重新计算 |

补充约束：

- `todayPlaceholder` 统一取保存当日的日期字符串，仅作为结构占位，不作为跨设备复用时的业务起点。
- `endMode` 是重复模板结束规则的唯一权威字段，不再同时保留 `长期有效开关 + durationDays` 的双重业务入口。
- `durationDays` 仅在 `endMode = 'duration'` 时允许大于等于 `1`。
- `durationDays` 的语义固定为“总持续天数，包含开始当天”：
  - `1` = 开始当天结束
  - `7` = 从开始日持续到第 7 天结束
- 非重复模板固定 `endMode = 'same-day'`、`durationDays = 1`。
- 重复模板：
  - `endMode = 'no-end' | 'week-end' | 'month-end'` 时，`durationDays = null`
  - `endMode = 'duration'` 时，必须提供有效 `durationDays`
- 自然周期边界固定为：
  - `week-end` = 首个匹配生效日所在自然周的周日结束
  - `month-end` = 首个匹配生效日所在自然月的月末结束
- 前后端 `normalizeDateStrategy()`、模板创建/更新服务、模板应用服务都必须识别并保留 `endMode` 与 `durationDays`，否则不允许进入实施。

#### 6. 模板编辑页与任务编辑页同构

模板编辑页尽量复用任务编辑页的布局语言：

- 先填任务内容，再填时间与重复，再给出保存动作
- 字段顺序与任务编辑页保持接近
- 文案尽量沿用任务编辑页已有表达
- 目标字段顺序明确固定为：
  - `任务名称`
  - `任务类型`
  - `星星 + 有效期`
  - `必做任务`
  - `任务描述`
  - `全天`
  - `时间范围`
  - `重复方式`
  - `自定义重复星期（仅 custom 时显示）`
  - `提醒`
  - `结束方式（仅重复模板显示）`
  - `持续天数（仅结束方式 = 持续天数时显示）`
  - `模板别名（可选）`
  - `启用模板`

模板特有输入收敛为两个：

- `模板别名（可选）`
- `启用模板`

#### 7. 预览区改为“轻量键值胶囊 + 结果说明”

模板编辑页的“当前预览”卡片不再直接展示纯值，而改为展示带字段语义的轻量胶囊：

- `重复 · 每天`
- `提醒 · 无`
- `星星有效期 · 永久`

设计要求：

- 每个胶囊都必须同时包含“字段名 + 值”
- 字段名使用更浅的辅助色，值保持正常可读权重
- 保持单层胶囊，不增加第二行字段名，不改成厚重卡片
- 单个值较短时也必须保留字段名，禁止再出现只有 `无`、`永久` 这类孤立值的展示
- 胶囊整体应弱化“可点击标签感”，更接近只读摘要信息：
  - 背景更淡
  - 边框更弱或可取消
  - 不使用过强阴影
  - 不与筛选标签共用过重的视觉语言
- 三个胶囊的高度、内边距和字号应与页面内其他摘要信息保持协调，不能压过主表单输入项

#### 7.1 “结束方式 + 持续天数”回到单行设置项节奏

`结束方式` 应成为重复模板时间范围的唯一显式配置入口，布局仍需保持与“时间与重复”分组一致的单行节奏：

- `结束方式`
  - 左侧：字段标题 `结束方式`
  - 右侧：单行 selector，选项为 `本周结束 / 本月结束 / 持续天数 / 长期有效`
- `持续天数`
  - 仅在 `结束方式 = 持续天数` 时展示
  - 左侧：字段标题 `持续天数`
  - 右侧：紧凑数字输入框 + `天`
  - 输入控件宽度固定，不占满整行
  - `按实际开始日计算结束日期` 保留为字段下方的轻量 hint，不再让输入框本身拆成第二行主布局

这样可以同时解决两个问题：

- 用户不必先理解“长期有效开关”和“持续天数”之间的组合关系
- `持续天数` 在视觉上不会被误认为更高优先级的复杂设置块

#### 8. 重复提示改为“结果导向文案”

重复提示文案不再强调“系统将自动调整”这类内部过程，而改为直接说明用户结果。

对于存在起始日与重复星期不匹配的场景，文案拆成两层：

- 主文案：说明“创建任务时将从哪一天开始执行”
- 次文案：说明“结束方式如何计算”

实现契约固定为两个独立展示字段：

- `resultPrimaryText`
- `resultSecondaryText`

约束：

- `resultPrimaryText` 必须始终存在于有重复提示的场景中
- `resultSecondaryText` 仅在需要补充结束方式说明时出现
- 禁止继续用单一 `repeatPreviewText` 字符串拼接“主结果 + 补充说明 + 过程解释”的混合文案

示例：

- 今天是周四，选择 `周一、周三、周五`：
  - 主文案：`创建任务时，将从下一个周五开始执行`
  - 次文案：`从实际开始日算，共持续 7 天`
- 今天是周四，选择 `周一、周三、周五`，结束方式为 `本周结束`：
  - 主文案：`创建任务时，将从下一个周五开始执行`
  - 次文案：`结束日期为该周周日`
- 今天是 4 月 28 日，结束方式为 `本月结束`：
  - 主文案：`创建任务时，将从今天开始执行`
  - 次文案：`结束日期为本月最后一天`
- 工作日模板但今天是周六：
  - 主文案：`创建任务时，将从下一个工作日开始执行`
- 休息日模板但今天是周二：
  - 主文案：`创建任务时，将从下一个休息日开始执行`

约束：

- 不再使用“开始日期不在所选重复星期内，系统将自动调整到第一个符合条件的日期”这一类系统过程型文案
- 如果 `endMode = 'duration'`，必须补充“按实际开始日计算”的结果说明
- 如果 `endMode = 'week-end'`，必须明确说明“结束于该周周日”
- 如果 `endMode = 'month-end'`，必须明确说明“结束于该月最后一天”
- 如果为长期有效，只保留“默认长期有效”说明，不再混入结束日期推导过程
- 结果文案的计算基点必须与 `applyTemplateToTaskForm()` 的真实应用规则一致，不允许出现“文案按首个匹配日解释、实际仍按今天起算”的双重语义

## 实施步骤

### 第1步：调整 `task-edit` 模板区层级

目标：

- 把模板区从“主模块”降级为“辅助条”

- 将无模板态从大按钮改为弱提示链接

- 弱提示点击后直接进入 `task-template-edit` 新建页，不经过模板页中转
- 右侧 `更多模板 >` 点击后进入模板页 `select` 模式
- 缩小模板区上下留白和边框存在感

- 进入页面后，视觉焦点首先落在任务表单而不是模板入口
- 用户能够区分“去创建模板”和“查看更多可用模板”

### 第2步：重做任务页模板标签

目标：

- 提高模板标签信息效率和视觉轻盈感

- 模板标签改成单层胶囊
- 只显示单个主名称
- 显示规则固定为：
  - `name` 非空且不等于 `taskPayload.title` 时显示 `name`
  - 其他情况显示 `taskPayload.title`

验收标准：

- 用户一眼能扫出常用模板，不会困惑“模板名称”和“任务名称”的区别

- 页面主体顶部使用双 tab：
  - `选择模板`
  - `管理模板`

  - 列表按“最近使用优先 + 使用次数次级排序 + 最近创建/最近编辑时间第三排序”固定输出
- `管理模板` tab：
  - 页面级主动作是 `新建模板`
  - 卡片整体点击进入编辑，不再依赖高权重 `编辑` 大按钮
  - `启用/停用`、`删除` 统一收纳到 `更多` action sheet
  - 首屏仅保留轻量搜索框和分类筛选
  - 状态筛选和排序切换不再作为常驻首屏控件
  - 列表固定按“最近编辑时间 -> 最近使用时间 -> 创建时间”排序
- 空态主体只保留一个 `创建第一个模板` 主按钮
- 页面内不再放置与导航标题重复的大标题卡片
- 页面外层 `container`、卡片间距、搜索筛选区 padding 参考 `task-edit` 页，不再额外营造独立后台视觉
- 同步清理仅服务旧双模式标题、旧状态筛选、旧排序筛选和旧卡片主按钮布局的状态字段、事件处理函数、样式和测试断言

验收标准：

- 导航标题、页内 tab、入口文案命名统一，不再混用 `选择模板 / 管理模板 / 模板管理`
- 从任务页进入模板页后，首屏焦点是“选模板”而不是搜索筛选器或“新建模板”
- `选择模板` 与 `管理模板` 的主任务清晰，不再混杂
- 用户能一眼理解：选择页是“点卡片回填”，管理页是“新建/编辑模板”
- 模板管理页空态只出现一个创建入口
- 模板管理页整体观感与任务管理页属于同一产品体系

### 第4步：简化模板编辑页字段暴露

目标：

- 减少用户无法理解的概念

实施：

- 移除绝对“日期范围”输入
- 移除“日期策略”选择器
- `模板名称` 文案改为 `模板别名（可选）`
- 保留 `启用模板`
- 移除 `结束日期过期时自动顺延` 开关
- 保存前自动执行：`name = alias.trim() || taskTitle.trim()`
- 保存前自动按重复类型推导 `dateStrategy.mode`
- 非重复模板保存时固定 `endMode = 'same-day'`、`durationDays = 1`
- 重复模板保存时只允许：
  - `endMode = 'week-end'`
  - 或 `endMode = 'month-end'`
  - 或 `endMode = 'duration' + durationDays`
  - 或 `endMode = 'no-end'`
- 同步删除仅为旧 `长期有效` 开关、旧 `默认持续天数` 单一方案和旧日期策略 UI 服务的表单字段、选项常量、事件处理函数和样式

验收标准：

- 用户进入编辑页后，能用与任务编辑页相近的心智完成设置
- 用户不再需要思考“模板日期到底该怎么填”

### 第5步：模板编辑页向任务编辑页同构

目标：

- 降低新功能学习成本

实施：

- 复用任务编辑页中的字段顺序、分组结构和主操作节奏
- 模板特有字段放在弱化位置
- 同步清理旧布局遗留的无效 class、仅旧按钮布局使用的样式和不再触发的事件分支
- 以以下顺序作为验收基线：
  - `任务名称`
  - `任务类型`
  - `星星 + 有效期`
  - `必做任务`
  - `任务描述`
  - `全天`
  - `时间范围`
  - `重复方式`
  - `自定义重复星期`
  - `提醒`
  - `结束方式`
  - `持续天数`
  - `模板别名（可选）`
  - `启用模板`

验收标准：

- 用户从“添加任务”切换到“新建模板”时，不会感到进入了完全不同的系统

### 第5.1步：重做模板编辑页“当前预览”

目标：

- 让用户在不增加阅读负担的前提下，一眼看懂每个预览值的归属

实施：

- 将“当前预览”中的纯值胶囊改为“字段名 + 值”的轻量键值胶囊
- 胶囊字段固定为：
  - `重复`
  - `提醒`
  - `星星有效期`
- 视觉上保留单层胶囊，但字段名与值区分轻重
- 进一步弱化胶囊的标签感，强化其“只读摘要”属性：
  - 降低背景对比度
  - 降低或移除边框强调
  - 不使用额外强调阴影
- 删除旧的纯值胶囊 class、仅支持纯值渲染的模板结构和对应测试断言
- 同步清理如果仅服务旧重标签风格的样式变量或 class，不保留双套胶囊视觉

验收标准：

- 用户不会再看到单独一个 `无` 或 `永久` 而无法判断语义
- 预览区仍保持紧凑，不会明显增加高度或显得拥挤
- 胶囊整体不会比主表单输入项更抢眼，观感更接近摘要而不是筛选标签

### 第5.1.1步：统一“结束方式 / 持续天数”布局节奏

目标：

- 让“时间与重复”分组内的设置项保持一致的扫描节奏

实施：

- 将 `结束方式` 调整为与同组字段一致的单行 selector
- `持续天数` 仅在 `结束方式 = 持续天数` 时显示，并调整为单行设置项
- 左侧保留标题，右侧为紧凑输入框和 `天` 后缀
- 输入框宽度固定，不使用占满整行的大输入框形态
- 字段说明 `按实际开始日计算结束日期` 降为下一行的轻量 hint
- 删除仅为旧 `长期有效 + 默认持续天数` 双字段方案和双行主布局服务的包裹结构与样式

验收标准：

- `结束方式` 与 `持续天数` 和同组的 `提醒`、`重复`、`全天` 等设置项在视觉节奏上保持一致
- 用户不会误以为该组配置是一个比其他项更重的高级配置块

### 第5.2步：重写重复提示文案为结果导向

目标：

- 让用户直接理解“创建任务后会发生什么”

实施：

- 将 `task-form-display` 中与重复冲突相关的过程型文案统一替换为结果型文案
- 自定义重复、工作日、休息日这三类偏移场景都要输出“将从哪一天开始执行”的表达
- 页面展示层改为消费 `resultPrimaryText` / `resultSecondaryText` 两个独立字段，而不是继续复用单一 `repeatPreviewText`
- 当 `endMode = 'duration'` 时，补充“结束日期按实际开始日计算”
- 当 `endMode = 'week-end'` 时，补充“结束日期为该周周日”
- 当 `endMode = 'month-end'` 时，补充“结束日期为该月最后一天”
- 当 `endMode = 'no-end'` 时，补充“默认长期有效”
- 清理旧的“系统将自动调整到第一个符合条件的日期”及等价过程型文案分支，不保留双套文案并存

验收标准：

- 用户读到提示后，能直接回答“会从哪一天开始”
- 用户能理解结束方式是基于“实际开始日”生效，而不是基于今天或保存模板当日算

### 第6步：模板日期应用规则收敛

目标：

- 让模板真正表现为“默认规则集合”

实施：

- `applyTemplateToTaskForm()` 不再依赖模板编辑时输入的绝对日期
- 非重复模板应用时固定填充 `今天 -> 今天`
- 重复模板应用时，先以“今天”为参考日寻找首个符合重复规则的生效日
- 若 `endMode = 'no-end'`，则填充为 `首个匹配生效日开始，无结束日期`
- 若 `endMode = 'duration'`，则按 `首个匹配生效日 + durationDays - 1` 计算结束日期
- 若 `endMode = 'week-end'`，则结束日期为 `首个匹配生效日所在自然周的周日`
- 若 `endMode = 'month-end'`，则结束日期为 `首个匹配生效日所在自然月的月末`
- 模板管理页摘要不再展示绝对日期，改为展示：
  - `本周结束`
  - `本月结束`
  - `持续 N 天`
  - `长期有效`

验收标准：

- 用户在模板管理页和模板使用时，都不会再把模板误解成“带固定日期的任务副本”
- 重复模板的结果提示文案与真实填充结果一致：提示从哪一天开始，实际也从哪一天开始

## 风险评估

### 风险1：体验优化时误伤已实现的模板主链路

风险：

- 页面重构可能导致模板选择、回填或管理链路回归
- “别名可选”如果只改文案不改保存逻辑，会与现有校验直接冲突
- 只删 UI 不删旧状态和旧事件，后续会形成隐藏分支和死代码，增加维护成本

应对：

- 前后端模板服务同步收敛 `dateStrategy` 契约，但不新增 REST 路径
- 表现层和服务层一起调整，不做只改 UI 的半截方案
- 页面保存前显式做 `name` 回填，避免触发前后端空名称校验
- 每删一个 UI 能力，都同步移除其无用状态、事件、样式与测试夹具
- 以现有模板相关测试为基础，同时补齐前后端 `endMode / durationDays` 定向测试

### 风险2：过度弱化模板入口，导致用户找不到

风险：

- 如果入口降权过头，用户反而无法发现模板能力

应对：

- 在 `task-edit` 顶部保留清晰但轻量的 `快捷填充` + `更多模板 >`
- 无模板时保留 `还没有模板，去创建 >`
- 模板页导航标题固定为 `任务模板`，页内通过双 tab 清楚标识当前子任务
- `选择模板` tab 保留清晰的“点击模板即可回填到任务表单”轻提示
- `管理模板` tab 保留明确 `新建模板` 页面级主动作

### 风险3：模板日期语义调整后，实施边界容易失控

风险：

- 如果一边改页面，一边不改服务层规则，最终会出现“UI 看起来没有日期，实际仍按旧绝对日期生效”的伪收敛
- 如果管理页摘要仍展示绝对日期，用户心智仍然会被拉回“任务实例快照”
- 如果 `本周结束 / 本月结束 / 持续天数` 的边界语义没有在服务层和展示层统一，仍会出现“文案这样说，实际那样算”的隐性回归

应对：

- 页面层与服务层一起修改
- 把“日期自动落定”写成显式验收标准和测试项
- 模板管理页同步去掉绝对日期摘要，避免一半新语义、一半旧语义
- 将 `week-end = 周日结束`、`month-end = 月末结束`、`durationDays` 包含开始当天写入共享 helper 和定向测试，禁止页面层各自解释

### 风险4：结果文案如果只换措辞、不统一 helper，仍会出现前后不一致

风险：

- 模板编辑页预览、任务编辑页重复提示、模板服务摘要如果各自拼文案，后续很容易再次出现多套表达并存

应对：

- 统一在展示 helper 中收口“键值预览”和“结果导向提示”
- 旧纯值拼接逻辑和旧过程型提示文案必须在本期实施中删除，不保留双轨实现
- 单测覆盖“字段名 + 值”和“结果导向提示”两个核心规则，避免后续回归

---

## 替代方案

### 方案A：直接修改原 `M21B1` 设计文档

不采用原因：

- 会把“基础能力设计”和“体验修正设计”混在一起，后续难以追踪边界

### 方案B：把体验优化延后到 `M21B3`

不采用原因：

- 当前问题直接影响用户对模板能力的理解，如果继续叠加 `M21B2` 功能，只会把复杂度继续放大

### 方案C：重新推翻模板页和任务页结构

不采用原因：

- 当前主链路已经稳定，没必要在 `M21B1` 后立刻大改架构
- 本期更适合做小范围、确定性的体验修正

---

## 结论

`M21B1-UX` 应作为 `M21B1` 完成后的短周期体验收尾阶段执行。它不仅修正当前表现层在视觉层级、概念暴露和操作节奏上的问题，也把模板日期语义收敛为“默认规则集合”，为后续 `M21B2` 和 `M21B3` 提供更稳定、更自然的用户基础。
