# 技术上下文

## 技术栈

### 前端框架
- **微信小程序原生框架**：充分利用小程序生态优势
- **JavaScript ES6+**：使用现代JavaScript语法
- **WXML/WXSS**：小程序模板和样式语言

### 架构设计
- **DDD架构**：领域驱动设计，清晰的分层架构
- **EventBus**：事件驱动架构，松耦合通信
- **依赖注入**：通过ServiceManager统一管理服务

### 核心依赖
- **Jest**：单元测试框架 (v29.5.0)
- **ECharts**：图表展示库 (微信小程序版本)

### 工具链
- **logger**：统一日志系统
- **batchUtils**：批量数据处理工具
- **StorageAdapter**：统一存储接口
- **formatUtils**：数据格式化工具
- **dateUtils**：日期处理工具

## 开发环境

### 开发工具
- **微信开发者工具**：小程序开发IDE
- **Node.js**：用于运行Jest测试
- **Cursor**：AI代码编辑器

### 项目配置
- **project.config.json**：小程序项目配置
- **jest.config.json**：测试配置
- **package.json**：项目依赖和脚本

### 版本控制
- **Git**：版本控制系统
- **分支策略**：功能分支开发模式

## 性能特性

### 分包策略
- **主包**：核心功能，体积最小化
- **分包按需加载**：优化首屏加载速度
- **资源预加载**：提升用户体验

### 存储优化
- **本地存储**：离线优先策略
- **数据分片**：避免单个数据过大
- **缓存策略**：合理的数据缓存机制

### 渲染优化
- **批量setData**：减少页面渲染次数
- **虚拟列表**：处理大量数据展示
- **图片懒加载**：优化图片资源加载

## 测试策略

### 测试框架
- **Jest**：主要测试框架
- **单元测试**：覆盖模型和服务层
- **集成测试**：测试完整业务流程

### 测试目标
- **覆盖率**：目标85%+
- **关键路径**：100%覆盖核心业务逻辑
- **回归测试**：确保功能稳定性

### 测试组织
```
test/
├── models/          # 模型层测试
├── repositories/    # 仓储层测试  
├── services/        # 服务层测试
├── integration/     # 集成测试
└── __mocks__/       # 测试模拟对象
```
